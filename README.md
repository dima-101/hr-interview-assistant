# HR Interview Assistant v2.0.0 (https://hr.dmitry-prompt.ru)

## О проекте

**HR Interview Assistant** — это вторая версия рабочего AI‑продукта для проведения структурированных HR‑интервью по заранее заданным профилям вакансий.

Проект одновременно является выпускной работой и прикладной разработкой, завершаемой в интересах производственного предприятия. На текущем этапе это не учебный макет, а рабочая система, в которой реализованы основные пользовательские и HR‑сценарии: просмотр материалов вакансии, прохождение интервью, server-side оценка ответов кандидата через LLM, формирование предварительной рекомендации для HR и работа через HR‑панель.

После завершения выпускного проекта система должна быть подготовлена к развёртыванию на хостинге предприятия и дальнейшему использованию в пилотном рабочем режиме.

## Назначение системы

HR Interview Assistant предназначен для автоматизации первичного HR‑скрининга кандидатов и поддержки HR‑специалиста при проведении интервью.

Система решает следующие задачи:
- предоставляет кандидату материалы по вакансии из карточки вакансии;
- проводит структурированное интервью по логике конкретной роли;
- фиксирует ответы кандидата в структурированном виде;
- выполняет предварительную оценку качества ответов на backend через LLM;
- формирует итоговый markdown‑отчёт по кандидату;
- выдаёт предварительную рекомендацию HR;
- предоставляет HR рабочую панель для управления вакансиями и просмотра отчётов.

## Текущий статус продукта

На текущем этапе проект является рабочим web‑приложением на FastAPI с frontend на Jinja2 / HTML / CSS / JavaScript и backend‑логикой оценки кандидата.

В проекте уже реализованы:
- публичные страницы и пользовательский сценарий интервью;
- карточки вакансий с Vacancy ID;
- передача структурированных ответов кандидата на backend;
- LLM‑оценка кандидата по логике вакансии;
- формирование и сохранение markdown‑отчётов;
- HR‑панель для просмотра отчётов и работы с карточками вакансий;
- базовая инфраструктурная готовность к VPS‑развёртыванию.

Интерфейс проекта выполнен в корпоративной стилистике предприятия. В кодовой базе также сохранены закомментированные элементы, связанные с логотипами предприятия и ссылкой на корпоративный сайт, чтобы они не были потеряны при финальной корпоративной адаптации.

## Архитектурная идея

Проект построен как модульная система, в которой логика интервью, карточки вакансий, оценка кандидата и HR‑интерфейс разделены по слоям и могут развиваться без полного переписывания приложения.

Ключевой принцип архитектуры:
- единое прикладное ядро FastAPI;
- структурированные карточки вакансий;
- backend‑сервис оценки кандидата;
- конфигурационный слой для режимов `demo` и `internal`;
- расширяемость под новые вакансии, новые сценарии и новых LLM‑провайдеров.

## Контуры эксплуатации

Проект поддерживает два контура эксплуатации:

### Demo
Контур для учебной защиты, портфолио и безопасной демонстрации возможностей продукта.

### Internal
Контур для последующего пилотного использования на стороне предприятия с корпоративным брендингом, рабочими вакансиями, HR‑отчётами и подготовкой к интеграции с внутренней инфраструктурой.

Оба режима должны работать на общей кодовой базе и переключаться через конфигурацию, а не через отдельные версии проекта.

## Ключевые компоненты

### Backend
Backend реализован на FastAPI и отвечает за маршруты приложения, работу с вакансиями, приём ответов кандидата, запуск server-side оценки, формирование отчётов и работу HR‑панели.

### Frontend
Frontend построен на Jinja2, HTML, CSS и JavaScript и обеспечивает пользовательский путь от просмотра вакансии до прохождения интервью и получения результата обработки.

### Карточки вакансий
Карточки вакансий содержат уникальный Vacancy ID, требования, red flags, банк вопросов, rubric, pass threshold и контекст роли. Они являются основой как для интервью, так и для backend‑оценки кандидата.

### LLM‑оценка
После завершения интервью frontend передаёт на backend структурированный массив ответов кандидата. Backend сопоставляет ответы с карточкой вакансии, использует LLM и формирует структурированный результат оценки и markdown‑отчёт.

### HR‑панель
HR‑панель предоставляет защищённый вход, просмотр отчётов, доступ к вакансиям и базовые операции по работе с карточками вакансий.

## Как работает система

Основной сценарий работы продукта:

1. Пользователь или HR выбирает вакансию.
2. Кандидат получает контекст и материалы по вакансии.
3. Кандидат проходит структурированное интервью.
4. Frontend собирает массив ответов кандидата.
5. Backend принимает данные интервью и находит карточку вакансии по `vacancy_id`.
6. LLM‑слой выполняет предварительную оценку кандидата.
7. Система формирует расширенный markdown‑отчёт.
8. HR просматривает отчёт и использует предварительную рекомендацию как инструмент поддержки принятия решения.

## Основные сущности данных

Система оперирует следующими сущностями:
- профиль вакансии;
- Vacancy ID;
- интервью кандидата;
- ответы кандидата;
- отчёт;
- HR‑пользователь;
- конфигурация бренда и режимов;
- журнал событий и ошибок.

Карточка вакансии должна включать как минимум:
- `required_skills`;
- `preferred_skills`;
- `key_soft_skills`;
- `red_flags`;
- `question_bank`;
- `evaluation_rubric`;
- `pass_threshold`.

- просмотр списка вакансий;
- просмотр проведённых интервью и отчётов;
- открытие сохранённых markdown‑отчётов;

## Требования к развёртыванию

Проект ориентирован на развёртывание как web‑сервиса на VPS с использованием uvicorn, systemd, Nginx и HTTPS.

Для production‑like развёртывания необходимо:
- использовать `.env` для секретов и параметров окружения;
- не хранить API‑ключи и пароли в Git;
- отключать debug‑режим в production;
- настраивать reverse proxy через Nginx;
- обеспечивать автозапуск приложения;
- проверять корректную работу статических файлов, шаблонов, сессий, HR‑авторизации и LLM‑части.

## Конфигурация

Система должна поддерживать конфигурацию:
- режима эксплуатации `demo` / `internal`;
- брендинга, логотипов и ссылок;
- параметров LLM‑провайдера;
- параметров таймаута и модели;
- секретов приложения и HR‑авторизации.

Минимальные переменные конфигурации для LLM‑части:
- `LLM_PROVIDER`;
- `LLM_TIMEOUT_SECONDS`;
- `OPENAI_API_KEY`;
- `OPENAI_MODEL`;
- `OPENAI_BASE_URL`;
- `GIGACHAT_API_KEY`;
- `GIGACHAT_MODEL`.
