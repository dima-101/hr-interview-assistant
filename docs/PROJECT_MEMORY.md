# PROJECT_MEMORY.md

## Название проекта
HR Interview Assistant

## Цель
Внутренний HR-сервис предприятия:
- просмотр вакансий;
- просмотр профилей вакансий;
- проведение интервью по блокам вопросов;
- формирование отчёта по кандидату.

## Текущая реализация
Стек:
- FastAPI
- Jinja2
- HTML
- CSS
- JavaScript

## Текущие страницы
- `/`
- `/about`
- `/vacancies`
- `/interview?vacancyid=...`
- `/report`

## Уже реализовано
- Список вакансий.
- Детальные страницы вакансий.
- Русские названия вакансий.
- Страница интервью.
- Навигация по вопросам.
- Поле имени кандидата.
- Поле ответа кандидата.
- Кнопка перехода к отчёту.
- Страница отчёта с тестовыми данными.
- Единый аккуратный дизайн.

## Важные вакансии
- `sales_soft_client_001`
- `design_engineer_rkd_001`
- `info_security_specialist_001`

## Важные требования предприятия
1. Сервис должен быть пригоден не только для учебной сдачи, но и для размещения на сервере предприятия.
2. Развёртывание желательно максимально простое.
3. Поддомен 3-го уровня будет выдан отдельно.
4. Дизайн должен быть в корпоративных цветах.
5. Нужна ссылка с сервиса на основной сайт предприятия.
6. На основном сайте предприятия будет ссылка на сервис.

## Реалистичный deployment-план
Есть два варианта:
1. Если хостинг поддерживает Python — разворачиваем FastAPI целиком.
2. Если хостинг не поддерживает Python — размещаем frontend на поддомене, backend переносим на отдельный сервер/VPS.

## Нельзя забыть
- выяснить тип хостинга;
- выяснить, можно ли запускать Python;
- выяснить, можно ли использовать systemd/nginx;
- выяснить, кто управляет DNS/поддоменами;
- согласовать корпоративный цвет;
- согласовать ссылку на основной сайт предприятия;
