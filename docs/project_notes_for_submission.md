# Project Notes for Submission

## Название проекта
**HR Interview Assistant v2.0.0**

## Краткое описание проекта

HR Interview Assistant v2.0.0 — это рабочий AI‑проект для проведения структурированных интервью с кандидатами по разным вакансиям.

Проект одновременно является выпускной работой и прикладной разработкой, завершаемой в интересах производственного предприятия. В текущем состоянии это не просто учебный набор материалов, а рабочий web‑продукт с пользовательским сценарием интервью, backend‑оценкой кандидата через LLM, формированием предварительной рекомендации для HR и доступной HR‑панелью.

Проект построен как модульная система, в которой:
- логика интервью и оценки опирается на структуру вакансии;
- карточки вакансий хранятся отдельно и могут развиваться без переписывания всей системы;
- backend формирует итоговый markdown‑отчёт по единой расширенной структуре;
- HR работает с результатами через защищённый интерфейс.

Такой подход делает проект пригодным не только для защиты, но и для дальнейшего пилотного использования на стороне предприятия.

## Цель проекта

Цель проекта — создать рабочий HR Tech продукт, который помогает HR‑специалисту:
- выбирать нужную вакансию;
- предоставлять кандидату контекст и материалы по вакансии;
- проводить интервью по заранее заданной структуре;
- получать структурированные ответы кандидата;
- выполнять предварительную AI‑оценку кандидата;
- формировать единый итоговый отчёт и предварительную рекомендацию для HR.

Дополнительная цель проекта — подготовить систему к последующему размещению на хостинге предприятия после завершения выпускного проекта.

## Что реализовано

В проекте на текущем этапе реализованы следующие ключевые части:

### 1. Web‑приложение
Проект реализован как web‑приложение на FastAPI с frontend на Jinja2, HTML, CSS и JavaScript.

Система включает:
- публичные страницы;
- список вакансий;
- карточки вакансий;
- сценарий интервью;
- страницу отчёта;
- HR‑авторизацию;
- HR‑панель;
- архив отчётов.

### 2. Карточки вакансий
В проекте используются структурированные карточки вакансий с уникальными Vacancy ID.

Каждая карточка содержит:
- основную информацию по вакансии;
- контекст роли;
- обязанности;
- обязательные и желательные требования;
- red flags;
- банк вопросов;
- rubric оценки;
- pass threshold;
- дополнительные поля для анализа кандидата.

### 3. Интервью и backend‑оценка
Кандидат получает материалы по вакансии и проходит структурированное интервью.

После завершения интервью frontend передаёт на backend структурированные ответы кандидата. Backend использует данные вакансии и LLM‑логику для предварительной оценки качества ответов и формирования результата по кандидату.

### 4. Итоговый отчёт
По результатам интервью система формирует расширенный markdown‑отчёт.

Отчёт включает:
- краткое резюме;
- оценку соответствия требованиям вакансии;
- сильные стороны кандидата;
- риски и red flags;
- оценку по rubric;
- итоговый балл;
- результат относительно порога прохождения;
- рекомендацию для HR;
- что проверить на следующем этапе.

### 5. HR‑панель
Для HR в проекте доступна рабочая панель.

Через неё HR может:
- авторизоваться в защищённой части системы;
- просматривать отчёты по соискателям;
- работать с карточками вакансий;
- добавлять карточки вакансий;
- изменять карточки вакансий.

### 6. Визуальная и корпоративная часть
Интерфейс проекта выполнен в корпоративной стилистике предприятия.

В кодовой базе сохранены элементы, связанные с логотипами предприятия и ссылкой на корпоративный сайт, чтобы после завершения выпускного проекта выполнить финальную корпоративную адаптацию и деплой на стороне предприятия.

## Почему проект сделан именно так

Проект собран не как один длинный текстовый документ, а как рабочая система с разделением по логическим слоям: интерфейс, вакансии, интервью, backend‑оценка, отчётность, HR‑панель и конфигурация.

Это даёт следующие преимущества:
- проект проще развивать без полной переработки архитектуры;
- новые вакансии можно добавлять без переписывания всей логики;
- HR получает единый стандарт интервью и отчётности;
- систему проще демонстрировать, поддерживать и передавать;
- продукт лучше подготовлен к практическому использованию на предприятии.

## Как демонстрировать проект

Во время демонстрации рекомендуется показать следующую последовательность:

1. Показать главную страницу и общий интерфейс проекта.
2. Открыть список вакансий и карточку одной из вакансий.
3. Показать, что кандидат получает материалы по вакансии и может перейти к интервью.
4. Запустить интервью и показать структуру вопросов.
5. Показать, что после завершения интервью формируется итоговый отчёт.
6. Показать HR‑панель, архив отчётов и работу с карточками вакансий.
7. Объяснить, что проект уже является рабочим продуктом и после защиты должен быть размещён на хостинге предприятия.

## Практическая ценность проекта

Проект демонстрирует навыки:
- проектирования прикладного AI‑продукта под реальный бизнес‑сценарий;
- разработки web‑сервиса на FastAPI;
- построения backend‑логики оценки кандидатов;
- проектирования структуры вакансий и отчётности;
- разработки HR‑интерфейса;
- подготовки продукта к deployment‑сценарию на стороне предприятия.

Практическая ценность проекта состоит в том, что он может использоваться как основа для пилотного HR‑инструмента на предприятии, а не только как демонстрационный учебный кейс.

## Масштабирование и развитие

Проект рассчитан на дальнейшее развитие.

В следующих этапах могут расширяться:
- набор вакансий;
- логика интервью и follow‑up вопросов;
- аналитика по кандидатам и вакансиям;
- роли пользователей;
- интеграции с внутренними и внешними системами;
- способы хранения данных и экспорта отчётов.

При этом базовая архитектура уже позволяет развивать проект без полного переписывания ядра.

## Итог

HR Interview Assistant v2.0.0 — это выпускной проект, который одновременно является рабочим прикладным продуктом для производственного предприятия.

Проект уже реализует основной пользовательский и HR‑контур: вакансии, интервью, backend LLM‑оценку, итоговые отчёты, предварительную рекомендацию для HR и работу через HR‑панель. Следующий практический этап — финальная подготовка и развёртывание на хостинге предприятия.
