# CHECKLIST_PRODUCTION.md

## Назначение

Этот чеклист используется для финальной проверки HR Interview Assistant v2.0.0 перед публикацией, развёртыванием на инфраструктуре предприятия и передачей проекта как рабочего продукта.

## 1. Архитектура и формат размещения

- [ ] Уточнён тип хостинга или сервера предприятия.
- [ ] Подтверждено, что окружение поддерживает запуск Python / FastAPI.
- [ ] Принято итоговое решение по формату размещения: полноценное FastAPI‑приложение на сервере предприятия.
- [ ] Подтверждён целевой режим эксплуатации: `internal`.
- [ ] Выбран рабочий поддомен предприятия.
- [ ] Подготовлена структура каталогов проекта на сервере.

## 2. Домен, сеть и доступность

- [ ] Создан поддомен для сервиса.
- [ ] Настроена DNS‑запись.
- [ ] Подключён HTTPS / SSL.
- [ ] Сервис открывается по внешнему или корпоративному адресу.
- [ ] Nginx корректно проксирует приложение.
- [ ] Проверен доступ к приложению снаружи и из внутренней сети предприятия, если это требуется.

## 3. Backend и приложение

- [ ] `uvicorn` запускается без ошибок.
- [ ] `systemd` или другой менеджер процессов настроен и работает.
- [ ] При перезапуске сервера сервис поднимается автоматически.
- [ ] Основные маршруты приложения открываются корректно:
  - [ ] `/`
  - [ ] `/about`
  - [ ] `/vacancies`
  - [ ] `/vacancies/{slug}`
  - [ ] `/interview?vacancyid=...`
  - [ ] `/report`
  - [ ] `/hr/login`
  - [ ] `/hr`
  - [ ] `/reports`
- [ ] Логи не содержат критических ошибок.
- [ ] Статические файлы и шаблоны отдаются корректно.
- [ ] Сессии и HR‑авторизация работают стабильно.

## 4. Интервью и оценка кандидата

- [ ] Соискатель может получить материалы по вакансии.
- [ ] Интервью запускается по выбранной вакансии.
- [ ] Вопросы подгружаются корректно.
- [ ] Ответы кандидата собираются в структурированном виде.
- [ ] Frontend отправляет данные интервью на backend без ошибок.
- [ ] Backend находит карточку вакансии по `vacancy_id`.
- [ ] Server-side оценка кандидата выполняется штатно.
- [ ] Формируется предварительная рекомендация для HR.
- [ ] При ошибке внешнего LLM API сценарий не ломается полностью.

## 5. Отчёты и HR‑панель

- [ ] Итоговый markdown‑отчёт сохраняется корректно.
- [ ] Отчёт открывается без ошибок.
- [ ] Архив отчётов доступен и работает стабильно.
- [ ] Фильтрация в архиве отчётов работает.
- [ ] HR может войти в HR‑панель.
- [ ] HR может просматривать отчёты по соискателям.
- [ ] HR может добавлять карточки вакансий.
- [ ] HR может изменять карточки вакансий.

## 6. Интерфейс и визуальная часть

- [ ] Интерфейс соответствует корпоративным цветам предприятия.
- [ ] Навигация работает корректно.
- [ ] Все основные кнопки работают.
- [ ] Формы и элементы управления понятны пользователю.
- [ ] Интерфейс не ломается на мобильном экране.
- [ ] Проверен визуальный фон сайта, если он используется.
- [ ] Сохранены логотипы предприятия и ссылка на основной сайт предприятия.
- [ ] С основного сайта предприятия может быть размещена ссылка на сервис.

## 7. Контент и данные

- [ ] Названия вакансий отображаются корректно.
- [ ] Vacancy ID отображаются корректно.
- [ ] Карточки вакансий содержат актуальные данные.
- [ ] Отчёты содержат понятные поля и структуру.
- [ ] Старые отчёты, если они сохранены, не мешают демонстрации.
- [ ] При необходимости демонстрационный архив очищен и заполнен актуальными отчётами нового формата.

## 8. Конфигурация и секреты

- [ ] `.env` вынесен из кода и заполнен корректно.
- [ ] Секреты не хранятся в Git.
- [ ] Debug‑режим отключён.
- [ ] Настроены параметры HR‑авторизации.
- [ ] Настроены параметры LLM‑провайдера.
- [ ] Проверены таймауты и параметры внешнего API.
- [ ] Проверены права доступа к файлам и каталогам на сервере.

## 9. Репозиторий и подготовка к передаче

- [ ] Репозиторий приведён в чистый публикационный вид.
- [ ] Временные файлы, локальные логи и лишние артефакты удалены или исключены из коммита.
- [ ] `.gitignore` настроен корректно.
- [ ] Подготовлены README и deployment‑документы.
- [ ] Подготовлена инструкция повторного деплоя.
- [ ] Подготовлены материалы для демонстрации и передачи проекта.

## 10. Финальная проверка перед запуском на предприятии

- [ ] Полностью пройден демонстрационный сценарий: вакансия -> интервью -> оценка -> отчёт -> архив.
- [ ] Проверена работа проекта в режиме `internal`.
- [ ] Подготовлен набор актуальных вакансий для стартового использования.
- [ ] Подготовлен набор актуальных отчётов для демонстрации и проверки.
- [ ] Подтверждено, что проект готов к размещению на хостинге предприятия после завершения выпускного проекта.

## 11. Бэклог следующего этапа

Следующие пункты не являются обязательными для production‑готовности текущей версии, но могут быть запланированы на следующий этап:

- [ ] Экспорт отчётов в PDF / DOCX.
- [ ] Расширение истории интервью.
- [ ] Дополнительные HR‑роли и пользователи.
- [ ] Углублённая аналитика.
- [ ] Интеграции с HRM / CRM / ATS.
- [ ] Расширение вариантов хранения данных.
- [ ] Подключение дополнительных LLM‑провайдеров.
